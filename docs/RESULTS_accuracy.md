# 精度の結果（eval_v1、2026-11）

問題は `dataset/eval_v1`（330 問: 文章だけ 180、画像付き 150）。測り方は [HOWTO_accuracy.md](HOWTO_accuracy.md)、
使った一覧は `tools/acc_lists/small.txt`（小型モデル）と `tools/acc_lists/quant.txt`（中型モデルの量子化）。
Jetson AGX Orin 64GB（MAXN）、1 問ずつ順番に投げたときの平均時間。

## まとめ

- **小型の判定モデルで、Clef-flash（9B）と同じかそれ以上の正解率が出る。** 一番よかったのは **d1-2B**（llama.cpp）で、
  正解率 98.5%、画像付き 0.15 秒（画像 448px）。3Hz の目標を大きく上回る
- **量子化しても正解率はほとんど落ちないが、速くもならない。** 判定は入力を 1 回通すだけ（prefill）で、
  計算の量で時間が決まるため。llama.cpp では量子化を強くするほど遅くなる（Clef-flash: BF16 0.95 秒 → Q2 1.37 秒）
- **大きいモデルを強く量子化しても、小型モデルには届かない。** Clef（27B）は Q2 でも 1 問 4 秒で、正解率も d1-2B より低い
- どのモデルも「点の数を数える」問題が苦手（20 問中 4〜17 問）。ここがモデルの差がいちばん出る

- Intern 0.8B と d3-edge は、画像を大きくすると看板の単語（大きな文字）を読み間違える（1024px で 1/30、3/30）

## 量子化で速くならない理由

判定は答えを生成せず、入力（文章 + 画像で数百トークン）を 1 回通すだけなので、メモリの読み出しより計算が律速になる。
重みだけを小さくする量子化（GGUF の Q8〜Q2、GPTQ の W4A16 など）は、計算の前に重みを元の精度に戻す手間が増えるだけで、計算量は減らない。
速くするには、モデルを小さくする（パラメータ数、MoE）、入力トークンを減らす（画像サイズ）、計算そのものを INT8 にする（W8A8。Orin は FP8 非対応）のどれかが必要。
